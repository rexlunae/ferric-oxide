# Ferric Oxide roadmap

The full plan, with the design and exit criteria for every phase, is the
[Roadmap chapter](docs/src/ferric-roadmap.md) of the book. This file tracks
progress against it. For what the system does today, read
[Implemented System](docs/src/ferric-oxide.md). "Merged" lists pull requests
that landed; it does not mean the phase is done. A phase is done only when its
exit criteria are met.

Phases run in dependency order, several in parallel. The two release milestones
are **M1 "Server/VM usable"** (Phases 0–4, P through P5, B, T, V and guest
virtualization) and **M2 "Workstation usable"** (M1 plus completed Phase S,
Phases 5–6 and the [Phase L Linux desktop compatibility profile](docs/src/ferric-roadmap.md#phase-l-linux-userspace-compatibility),
with the wasm userland as default if its benchmark gate passes).

## Current completion priority

Finish **Phase S: timers, tickless scheduling and kernel async** before starting
new Phase L Linux ABI implementation. It is started work with merged clock/timer
and portable executor foundations; the running kernel still uses periodic
scheduling and blocking ring workers. The
[completion order](docs/src/ferric-roadmap.md#completion-priority-and-order)
is corrected baselines, clock/deadline and scheduler integration with topology
and preemption work, async scheme/ring integration, reservations, then stress
and measured adoption gates. Build/boot fixes can continue during this work.

## Updating this file

When you merge work that belongs to a roadmap phase, add its pull request to
the phase's row in the same pull request or right after it, move items from
"Open or next" to "Merged", update the status, and change the date above. Mark
a phase done only when its exit criteria in the
[Roadmap chapter](docs/src/ferric-roadmap.md) are met. Changes to the plan itself
go in that chapter.

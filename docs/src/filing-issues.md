# Filing Issues

[GitHub issues](https://github.com/rexlunae/ferric-oxide/issues) are how you
reach the developers. They keep the discussion of a bug or a feature in one
place, linked to the pull requests that fix or build it.

Use an issue for:

- **Bugs and build failures.** Use the bug report template and follow
  [Creating Proper Bug Reports](./creating-proper-bug-reports.md).
- **Hardware reports.** Say what worked and what didn't on a real machine, with
  the commit you tested. Successful results can also go straight into
  [HARDWARE.md](https://github.com/rexlunae/ferric-oxide/blob/main/HARDWARE.md)
  in a pull request.
- **Proposals.** Label the issue `proposal` and describe the problem and the
  approach before writing a large change to a kernel interface, a scheme, the
  file system format or the build system layout.
- **Questions.** If the book doesn't answer it, ask. A question that comes up
  often is a sign a page needs improving.

Search open and closed issues before filing, and watch your issue so you can
answer follow-up questions. GitHub notifies the maintainers of new issues; you
don't need to post the link anywhere else.
